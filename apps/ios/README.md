# WeldSuite for iOS

The native iOS apps, in Swift and SwiftUI (iOS 17 and later). They replace
the Expo apps in `apps/mobile`: WeldPass, WeldBooks, WeldMail, WeldCalendar,
WeldChat, WeldDesk and WeldHR so far.

| Path | What |
|---|---|
| `WeldKit/` | A local Swift package: `CoreAPI` and one API target per app (`WeldPassAPI`, `WeldChatAPI`, …; clients generated by swift-openapi-generator from `apps/mobile-shared/openapi`), `WeldCore` (server, WeldID sign-in through AppAuth, workspace, Keychain, app lock, the realtime socket, push, date and money formatting), `WeldUI` (tokens, `SessionGate`, the shared components and the settings every app has) |
| `Apps/<App>/` | One app each: `WeldBooks`, `WeldMail`, `WeldCalendar`, `WeldChat`, `WeldDesk`, `WeldHR` (`com.weldsuite.<app code>`), with sources, resources and tests |
| `Apps/WeldPass/` | WeldPass (`com.weldsuite.weldpass`): sources, resources, tests |
| `Apps/WeldPassAutofill/` | WeldPass's AutoFill credential provider extension (`com.weldsuite.weldpass.autofill`). It reads the offline copy through the App Group `group.com.weldsuite.weldpass` and the Keychain group `com.weldsuite.weldpass.shared`, which signed builds need in the provisioning profiles. |
| `Project.swift` | The Xcode project, generated by Tuist. The `.xcodeproj` isn't committed. |

## Build and run

On a Mac with Xcode 26 and [mise](https://mise.jdx.dev):

```bash
cd apps/ios
mise install            # Tuist, pinned in mise.toml
tuist generate          # writes and opens WeldSuite.xcworkspace
```

Run the app's scheme (`WeldPass`, `WeldChat`, …). The first build asks you to trust the
swift-openapi-generator plugin. Debug builds start on the EU test cluster
(`app.test.weldsuite.eu`), release builds on `app.weldsuite.eu`.

What CI runs (`Native · iOS`):

```bash
cd WeldKit && xcodebuild test -scheme WeldKit-Package -destination 'platform=iOS Simulator,name=iPhone 17'
cd .. && tuist generate --no-open
xcodebuild test -workspace WeldSuite.xcworkspace -scheme WeldPass -destination 'platform=iOS Simulator,name=iPhone 17'   # and every other app's scheme
```

Strings, tokens and the API contract come from `apps/mobile-shared`; run
`pnpm mobile:generate` from the repo root after changing them.

## Release

Store builds come from the **Mobile native release** workflow
(`.github/workflows/mobile-native-release.yml`), run by hand on `main`. It
archives with automatic signing through an App Store Connect API key from the
`mobile-release` environment and uploads to TestFlight; submitting for review
is done in App Store Connect. The version is `MARKETING_VERSION` in
`Project.swift`; the workflow sets the build number
(`CURRENT_PROJECT_VERSION`) for the app and its extension.
