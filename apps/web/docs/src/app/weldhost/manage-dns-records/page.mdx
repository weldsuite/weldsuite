# Manage DNS records

Add, edit, and delete DNS records for a domain that is already connected in WeldHost. {{ className: 'lead' }}

<Note>
  Your domain must be connected with nameservers pointing at WeldHost before records appear and can be edited. See the [WeldHost overview](/weldhost) if the DNS tab is not ready yet.
</Note>

## Open the DNS tab

1. Open **WeldHost** in WeldSuite.
2. Go to **Domains**.
3. Select the domain you want to configure.
4. Open the **DNS** tab.

You see a table of records (type, name, content, TTL) plus search and type filters. Changes sync to the Cloudflare zone for that domain.

## Add a record

1. Click **Add Record** (or **New record**).
2. Choose a **Type**.
3. Enter the **Name** — use `@` for the apex (root) of the domain, or a subdomain such as `www` or `mail`.
4. Enter the **Value** (IP address, hostname, or text, depending on the type).
5. Set **TTL** in seconds if you need something other than the default (`3600`). Leave it empty or use Auto when you want the platform default.
6. For **MX** or **SRV** records, set **Priority**.
7. Save the record.

Name must be 1–255 characters. Value must be 1–2048 characters. TTL, when set, must be between 1 and 86400. Priority for MX/SRV must be between 0 and 65535.

## Supported record types

WeldHost lets you create these types from the DNS tab:

| Type | Typical use |
| --- | --- |
| **A** | Point a name at an IPv4 address |
| **AAAA** | Point a name at an IPv6 address |
| **CNAME** | Alias a name to another hostname |
| **MX** | Mail servers for the domain (includes priority) |
| **TXT** | Verification strings, SPF, and other text |
| **NS** | Delegate a subdomain to other nameservers |
| **SRV** | Service discovery (includes priority) |
| **CAA** | Restrict which CAs may issue certificates |

PTR and SOA records are not offered in the UI — they are managed by the registry or DNS provider infrastructure.

## Edit or delete a record

- **Edit** — use the pencil action on the row, change the fields, and save.
- **Delete** — use the trash action, then confirm. The confirm dialog shows the type and name of the record you are removing.

Unlocked records can be changed freely. If edit and delete are disabled, the record is locked (see below).

## Locked records

Some records are managed by WeldSuite for other apps — for example WeldMail MX and SPF entries. Those rows show a **lock** badge.

- You cannot edit or delete locked records in the DNS tab.
- The server rejects changes to locked records even if the UI were bypassed.
- To change mail-related DNS, use the WeldMail / email domain flow rather than editing those rows by hand.

## Find records

- Use the **search** box to match on name or content.
- Use the **type** filter chips to show only certain record types (or All).
- Use the **lock** filter to show locked or unlocked records only.

If nothing matches, clear filters or broaden the search.

## Examples

These examples use `example.com`. Replace with your domain. Values are illustrative — use the IPs or hostnames your service gives you.

### Apex A record

| Field | Value |
| --- | --- |
| Type | A |
| Name | `@` |
| Value | `203.0.113.10` |
| TTL | `3600` |

### www CNAME

| Field | Value |
| --- | --- |
| Type | CNAME |
| Name | `www` |
| Value | `example.com` |
| TTL | `3600` |

### TXT verification

| Field | Value |
| --- | --- |
| Type | TXT |
| Name | `@` (or the host your provider specifies) |
| Value | `verification-token=…` |
| TTL | `3600` |

After you save, allow a short time for DNS to propagate. Most changes are visible quickly once the zone is active in WeldHost.
