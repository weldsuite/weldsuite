# WeldSuite Rust backend

The backend for the Kubernetes deployments, the EU and self-hosted editions
(ADR API-014). It builds one binary, `weldsuite`, shipped as one container image
and installed with the Helm chart in `deploy/helm/weldsuite`. The Global
edition keeps the TypeScript workers on Cloudflare; modules are ported from
them one at a time, and both implementations answer the same API. The design, the decisions and the phase plan live in
the private docs repo: `design/platform/editions-and-self-hosting.md` and
`editions-and-self-hosting-phases.md` in `weldsuite/weldsuite-documentation`.

Status: **phase P1** (foundations). `weldsuite serve` runs: session tokens,
workspace → tenant database, permissions, probes, graceful shutdown, JSON logs,
and the first ported route, `GET /api/me/permissions`. Business modules come
next, one at a time.

## Layout

```
rust/
  Cargo.toml            workspace: shared package metadata, lints, dependency versions
  rust-toolchain.toml   pinned compiler (CI and local builds use the same one)
  deny.toml             cargo-deny: allowed licences, advisories, sources
  clippy.toml           clippy settings (product names allowed in docs)
  .cargo/config.toml    build settings (prebuilt NASM for aws-lc on Windows)
  catalogs/*.json       generated by `pnpm rust:catalogs` from the TypeScript catalogs; don't edit
  Dockerfile            the image (distroless, nonroot); build context is rust/
  bins/weldsuite/       the one binary: `serve` now; consume, cron and admin commands later
  crates/kit/           response envelope, errors, ids, CORS, request id (worker-kit in TS)
  crates/catalogs/      entity events, permission keys, flags, API modules, origins as constants
  crates/auth/          Clerk session tokens (azp, clock skew, fva) and step-up second factor
  crates/permissions/   @weldsuite/permissions: matching, per-app checks, grants, resolution, route layer
  crates/db/            master DB, workspace → tenant pool, database_url decryption, permission lookups
  crates/ports/         ports (cache, event bus, realtime, flags) and their in-memory test doubles
  crates/events/        @weldsuite/entity-events: the hub message and the fire-and-forget publisher
  crates/adapters-oss/  open-source adapters: Valkey cache + pub/sub, NATS JetStream, flags in the master DB
  deploy/helm/weldsuite the Helm chart
  deploy/kind/          a local kind cluster smoke test (also run in CI)
```

## Commands

From the repo root:

```bash
pnpm rust:catalogs  # re-export rust/catalogs/ from the TypeScript catalogs
pnpm rust:fmt     # format
pnpm rust:lint    # rustfmt --check + clippy, warnings are errors
pnpm rust:test    # tests
pnpm rust:deny    # licences, advisories, duplicate crates, sources (needs cargo-deny)
```

Or `cargo …` inside `rust/`. The integration tests need throwaway services
and are skipped without them: Postgres in `WELDSUITE_TEST_DATABASE_URL`
(`weldsuite-db`, and the flag table of `weldsuite-adapters-oss`; CI starts
one), Valkey in `WELDSUITE_TEST_VALKEY_URL` (`redis://…`) and NATS with
JetStream in `WELDSUITE_TEST_NATS_URL` (`nats://…`).

## Running it

```bash
docker build -t weldsuite:dev rust
rust/deploy/kind/smoke-test.sh     # kind cluster + Postgres + the chart; probes and /health checked
```

The server reads environment variables only (`bins/weldsuite/src/config.rs`):

| Variable | |
|---|---|
| `DATABASE_URL_MASTER` | master database (required) |
| `CLERK_JWT_KEY` or `CLERK_JWKS_FILE` | session token key: PEM, or a JWKS file (required) |
| `DATABASE_ENCRYPTION_KEY`, `DATABASE_ENCRYPTION_KEY_V2` | open encrypted `workspaces.database_url` |
| `CLERK_AUTHORIZED_PARTIES` | extra origins allowed as `azp` |
| `PERMISSIONS_APP_ENFORCE` | `true` refuses per-app denials instead of logging them |
| `PORT`, `HOST` | listen address (default `0.0.0.0:8080`) |
| `ENVIRONMENT`, `LOG_FORMAT` (`json`/`text`), `RUST_LOG` | reporting and logs |
| `DATABASE_MASTER_MAX_CONNECTIONS`, `TENANT_POOL_MAX_CONNECTIONS`, `TENANT_POOLS_MAX`, `WORKSPACE_CACHE_TTL_SECONDS` | pools and the workspace cache |
| `SHUTDOWN_DELAY_SECONDS` | how long `/readyz` fails after SIGTERM before connections stop |

Probes: `/livez` (the process answers), `/readyz` (the master database answers
and the pod is not draining). `/health` keeps the workers' JSON.

Not there yet: fetching and refreshing a JWKS over HTTP (mount the document
instead), OIDC providers other than Clerk (ADR SEC-012), the Neon API fallback
for a workspace without a stored `database_url` (the Kubernetes editions
always store it), and Clerk member linking on `/api/me/permissions`. The pinned toolchain installs itself through rustup
on first use. `cargo install cargo-deny --locked` for the deny check.

## Rules

- **Lints are workspace-wide** (`[workspace.lints]` in `Cargo.toml`): `unsafe`
  is forbidden and clippy's pedantic group is on. Every crate opts in with
  `[lints] workspace = true`.
- **Dependency versions live in `[workspace.dependencies]`**; crates use
  `dep = { workspace = true }`.
- **A new licence in `deny.toml` is a licensing decision.** The backend ships
  under AGPL-3.0-only (OPS-002); say why in the PR.
- **Module crates never depend on each other**, only on shared crates. This is
  how the module boundaries of API-004 are enforced in Rust.
- **Bumping the toolchain** is its own PR: `rust-toolchain.toml` and
  `rust-version` in `Cargo.toml` together.
